= Adobe Source fonts in a package

https://github.com/fontist/source-fonts/actions/workflows/build.yml[image:https://github.com/fontist/source-fonts/actions/workflows/build.yml/badge.svg[]]

== Purpose

This repository is used to produce a single package for Adobe Source fonts
for metanorma's PDF pipeline (mn2pdf / Apache FOP).

== Contents

One package: `source-fonts-{version}.zip`, with a flat `fonts/` directory
containing static fonts only:

* https://github.com/adobe-fonts/source-sans[Adobe Source Sans Pro] (last
  release published under the legacy family name; later releases rename the
  family to "Source Sans 3", which metanorma stylesheets do not reference)
* https://github.com/adobe-fonts/source-serif[Adobe Source Serif Pro] (same
  legacy-name reasoning; later releases rename to "Source Serif 4")
* https://github.com/adobe-fonts/source-code-pro[Adobe Source Code Pro]
* https://github.com/adobe-fonts/source-han-sans[Adobe Source Han Sans] as
  per-weight TTCs (TrueType conversions with the legacy family names, since
  FOP cannot use the variable fonts Adobe ships at current versions)

Each font file keeps the family name of the release it was built from; the
file names in the package follow the v1.0 contract
(`SourceSansPro-*.ttf`, `SourceSerifPro-*.ttf`, `SourceCodePro-*.ttf`,
`SourceHanSans-{weight}.ttc`), so consumers (fontist formulas, mn2pdf
manifests) can move between v1.0 and v1.4+ without changes.

Adobe does not publish static TrueType builds of current Source Han Sans
under the legacy names — the 2.005R assets are variable fonts and CFF
OTFs — so the TrueType conversion is the only source that satisfies both
the format FOP renders and the names metanorma references. The Latin
fonts remain at the last legacy-named releases for the same reason;
beyond them, Adobe renames the family, which is a fleet-wide breaking
change for metanorma.

== Release gating

Every push and pull request runs `make test`
(link:test/mn2pdf_compat.py[]), which fails the build when a font:

* carries variable-font tables (`fvar`/`gvar`) — FOP renders a variable
  font as its default instance only, so all weights would come out wrong,
* or its filename trips mn2pdf's variable-font refusal heuristic
  (`variablefont`/`wght`),
* or a required legacy family ("Source Han Sans", "Source Sans Pro",
  "Source Serif Pro", "Source Code Pro", and the Han Sans region
  variants) is missing or lacks Regular/Bold styles.

The release job additionally renders every required family at Regular and
Bold through Apache FOP itself, and publishes only if that render
succeeds. v1.3 shipped variable-font CJK files and renamed Latin families;
this gate exists to make that class of breakage impossible to publish.
